# Админка сайта

Панель управления лежит на сайте по адресу `https://ВАШ-ДОМЕН/volgina/admin/`. Ссылки на неё на публичных страницах нет, поисковикам она закрыта.

## Что умеет

- **Отзывы.** Гость оставляет отзыв через форму на сайте, и он попадает во вкладку «Ждут проверки». Владелец нажимает «Опубликовать» (отзыв сразу появляется на сайте) или «Отклонить» (посетители его не увидят). Текст можно поправить до публикации, опубликованный отзыв можно снять с сайта, поднять или опустить стрелками, удалить. Отзыв из мессенджера добавляется вручную, при желании со скриншотом оригинала.
- **Тексты.** Все тексты страницы разбиты на разделы. После «Сохранить и опубликовать» сайт обновляется сразу. Пустое поле возвращает исходный текст, у каждого изменённого поля есть «Вернуть исходный».
- **Фотографии.** Замена шести фото на страницах (знакомство, четыре формата, раздел «Почему со мной комфортно»), галерея: добавление нескольких фото сразу, порядок, описание для незрячих и поисковиков, удаление, возврат исходных. Размеры и WebP-версии создаются автоматически. Главное фото первого экрана с вырезанным фоном заменяется отдельно.
- **Настройки.** Ссылки на ВК и MAX, телефон, смена пароля, проверка сервера (права на запись, WebP).

## Как это устроено

Сайт остаётся статичным `index.html`, который админка перегенерирует при каждом сохранении из шаблона `admin/template.html` и данных. Посетители не нагружают PHP, а если админка сломается, сайт продолжит работать. Перед каждым обновлением старая страница сохраняется в `volgina-review-data/backups/` (последние 15).

Приватные данные лежат вне `public_html`, в `lazurin/volgina-review-data/`:

| Файл | Что внутри |
| --- | --- |
| `reviews.json` | все отзывы со статусами `pending` / `published` / `rejected` |
| `content.json` | изменённые тексты, фото, порядок галереи, контакты |
| `admin.json` | хеш пароля (сам пароль нигде не хранится) |
| `sessions/`, `throttle.json`, `backups/` | сессии, защита от подбора пароля, копии страницы |

Загруженные фото складываются в `images/uploads/`, там запрещено выполнение любых скриптов.

## Первый запуск

1. Распаковать архив в `lazurin/public_html/volgina/` (вместе с папкой `admin`).
2. Открыть `https://ВАШ-ДОМЕН/volgina/admin/`.
3. Ввести **код первого входа** (он лежит в `admin/config.local.php` и передаётся владельцу отдельно, в репозиторий его не кладут) и придумать пароль не короче 10 символов.
4. После этого код больше не нужен, а страница создания пароля недоступна.

Права: PHP должен писать в `public_html/volgina/` (файл `index.html`, папка `images/uploads/`) и создавать `lazurin/volgina-review-data/`. Раздел «Настройки → Проверка сервера» подсвечивает, чего не хватает.

## Безопасность

Вход по паролю (`password_hash`), 5 неверных попыток блокируют вход на 15 минут. Сессия живёт 12 часов, cookie `HttpOnly` и `SameSite=Strict`. Все изменения защищены CSRF-токеном. Тексты гостей экранируются при выводе, загрузки проверяются по содержимому и пересохраняются в WebP, исходный файл не сохраняется, метаданные вырезаются.

## Как восстановить доступ

Забыли пароль: удалите файл `volgina-review-data/admin.json` через файловый менеджер хостинга и откройте админку заново, она снова предложит ввести код первого входа и задать пароль. Содержимое сайта при этом не меняется.

Разблокировать вход раньше 15 минут: удалите `volgina-review-data/throttle.json`.

Вернуть прежнюю версию страницы: возьмите нужную копию из `volgina-review-data/backups/` и положите как `public_html/volgina/index.html`.

## Локальная разработка

```
php -S 127.0.0.1:8210 -t volgina
```

Данные при этом лежат в `.dev-data/` внутри проекта (в git не попадают), код первого входа берётся из `volgina/admin/config.local.php` (создайте из `config.local.php.example`).
